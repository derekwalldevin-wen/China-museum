# 页面浏览可靠性优化设计

## 目标

保留现有深色古地图、3D 沙盘和博物馆目录视觉，优先解决真实浏览中的误点、返回层级、移动端拥挤、弹层可访问性和后台渲染浪费。第一轮不重做数据结构，不接入新的文物图片，也不引入完整路由页面重构。

## 导航架构与数据流

页面层级统一为 `总览 → 省份 → 博物馆 → 文物`。省份、博物馆和文物 ID 写入 URL 查询参数，并用 History API 保存层级。浏览器后退、界面返回按钮和 Esc 都按同一层级规则工作。文物打开状态从 `MuseumDetail` 的局部状态提升到 `App`，避免 URL、弹层和全局快捷键彼此不一致。馆内切换文物或同省切换博物馆使用替换当前历史项，避免产生大量无意义的后退步骤。

## 组件调整

- `App`：集中维护导航状态、URL 同步和分层关闭逻辑。
- `FilterBar`：桌面保留朝代按钮；手机改成紧凑的朝代与类别下拉框。
- `App` 移动端工具行：增加明确的省份选择器，保证所有行政区都能可靠到达。
- `TerrainScene`：省份标记改为语义按钮；手机端缩小为非交互提示点，主要交互交给地形点击和省份选择器；博物馆详情打开时暂停昂贵的 3D 合成渲染。
- `MuseumDetail`：改为受控文物弹层；增加 dialog 语义、初始焦点、Tab 焦点约束、Esc 仅关闭当前文物以及背景不可交互。
- `ArtifactCard`：长卷、立轴等书画使用完整图像适配，避免 `object-cover` 将超长图片放大成模糊色块。

## 错误处理与测试

无效 URL 参数回退到最近的合法层级。图片加载失败继续使用现有线刻回退。回归覆盖 1280×720 桌面、390×844 手机、键盘 Tab/Esc、搜索直达、浏览器后退/前进、省份误点、长卷展示和详情打开后的 3D 暂停。构建继续以 `npm run build` 为发布门槛；未使用的通用 UI 模板 lint 问题单独处理，不混入本轮核心页面修改。
