# 故事目录分片验收设计

当前 `e2e-stories.mjs` 将六条游线和不断增加的独立故事在同一 CDP 标签页中连续导航。目录扩充至85件后，两次完整扫描在不同旧故事位置出现 `Runtime.evaluate` 超时；两次结果既不能证明页面错误，也不能证明全量通过。

比较三种方案：单纯延长CDP超时成本最低，但上一轮60秒仍失败；重启浏览器后复跑可减轻累积状态，却不能可靠定位失败件；按文物ID稳定分片、每件打开并关闭隔离页面，可保存逐件证据，失败后只重跑该分片。因此选择第三种。脚本从所有故事JSON读取并按ID去重，固定排序，参数指定分片总数和索引；每件同时检查桌面和390px手机的直接URL、四章三细节、关联入口、来源链接、筛选参数、横向溢出与运行异常。每完成一件就原子写当前分片结果，脚本结尾仅在全分片全部通过时返回0，不能把未运行件计通过。

此脚本只改变测试层，不改变应用、图片、授权或导航。仍保留现有长时游线脚本作为专项交互验证。分片报告须汇总唯一85个ID在两种视口的覆盖，遇到CDP偶发失败记录对应ID并重跑，直到结果可复现或明确产品缺陷。项目无Git元数据，不执行提交。
