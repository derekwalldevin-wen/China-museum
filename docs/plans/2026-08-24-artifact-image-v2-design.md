# 文物图片 V2：溯源、双图片与 P1 重置设计

## 1. 视觉策略

本批采用用户确认的“分类型统一”。统一项是 4:5 卡片比例、近黑暖灰背景、柔和顶部博物馆展柜光、克制的金褐与朱砂色域、无文字无水印、主体边缘完整和可供 UI 印章使用的右下安全区。变化项由文物类型决定：单体器物采用高保真暗色影棚；长卷与书迹采用卷轴或装裱状态的代表性卡片图，并在详情保留完整原卷；编钟等群组展品保留相对位置和空间尺度，以受控展陈场景代替孤立抠图。

“统一”不允许改变器形、纹样、铭文、材质或时代特征。生成时把现有真实图片作为编辑目标和史实参考，把已完成的 1122×1402 候选图作为风格参考。视觉验收和史实验收分离：Codex 可以完成构图、清晰度、风格和 UI 适配检查，但没有博物馆权威资料时，史实状态保持 `pending`，不得写成已确认。

## 2. 数据模型与兼容

`images.json` 顶层 `src`、`credit`、`ai` 暂时保留，保证其余 166 件无需立即迁移。新增 `variants.card` 与 `variants.detail`，每个变体包含 `src`、`kind`、`fit`、`credit`、`provenance` 和 `review`。`kind` 明确为 `source` 或 `ai`；AI 溯源记录生成服务、提示词版本、生成日期、参考文件和提示词；真实来源记录来源页、作者/机构、许可及核验日期。审核记录将 `visual` 与 `historical` 分开。

解析器按角色返回完整的 `ResolvedArtifactImage`。若角色变体不存在，则回退顶层旧图。前端加载失败时先尝试旧图；只有新图和旧图都失败才显示 `ArtifactArt`。这使新批次可以渐进上线，同时保留回滚路径。

## 3. 长卷双图片数据流

卡片、博物馆缩略图请求 `card` 变体，详情请求 `detail` 变体。P1 中 6 件书画/文书类长卷的 `card` 使用 AI 生成的 4:5 代表性展陈图，避免完整横卷在卡片中缩成细线；`detail` 暂时使用原始来源图并采用 `contain`，确保用户仍能看到完整作品结构。详情标签因此显示真实来源说明，卡片则显示“AI 复原示意”。

后续如获得更高清的公共领域全卷，可只替换 `detail.src` 和来源记录，不需要重做卡片图或组件。未来深度浏览需要瓦片时，可在 `detail` 下扩展 `tiles`，本轮不提前实现。

## 4. P1 批次与验收

首批 25 件分为 6 件长卷/文书、2 件群组或复杂空间展品、17 件单体器物。`gg-gzdc` 与 `gg-qljs-v2` 已有候选图，先复核后复用；其余逐件生成。最终图片进入 `public/artifacts-v2/p1/`，旧图继续留在 `public/artifacts/`。每件图像记录最终提示词、参考图、生成日期和审核状态。

验收要求：文件可解析；卡片短边至少 900px；主体在 4:5 卡片中可辨认且不被印章遮挡；背景、光线和色域与批次一致；长卷卡片不再表现为细线；群组构件关系不被打散；无新增文字、徽标或水印；详情标签与当前显示变体的真实 `kind` 一致。自动检查覆盖路径、尺寸、元数据、构建和审计，人工接触表覆盖风格与构图，浏览器覆盖卡片、详情和触控页面。

## 5. 错误处理与回滚

新图片路径加载失败时，组件自动尝试顶层旧图；旧图也失败时才显示线刻。图片 V2 不覆盖原文件，因此任一条记录可通过删除 `variants` 快速回滚。生成失败只影响单件任务，不阻塞已经验收的其他图片。候选图在写入生产目录前必须通过视觉检查；未通过的版本保留在候选目录，不进入 `images.json`。
