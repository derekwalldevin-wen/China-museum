# 地图性能与触控优化设计

## 诊断

- 地图代码虽已独立分包，但进入首页后立即下载、解析并同步生成高密度地形；加载遮罩同时阻断了目录入口。
- 现有标准档仍启用 Bloom、调色后期和连续 60fps 渲染，移动设备的 GPU 与电池成本偏高。
- `pointermove` 在触屏上仍执行地形射线检测；单一按下坐标也无法可靠区分轻点、拖动和双指手势。
- WebGL 上下文丢失时直接刷新页面，会破坏用户当前浏览位置。

## 方案比较

### A. 渐进自适应（采用）

根据屏幕、指针、内存、CPU、节流模式和低动态偏好分为高、标准、节能三档。降低几何密度与 DPR，非高档关闭后期，高档后期异步载入；限制帧率并在静止时休眠。优点是保持现有风格与数据结构，风险最低。

### B. 双渲染器

移动端改用独立 2D Canvas 地图，桌面继续 Three.js。首屏和低端表现最佳，但需要维护两套命中检测、投影与视觉实现，当前阶段成本过高。

### C. 服务端预烘焙

把地形预烘焙为纹理或 glTF，并通过 CDN 分级传输。长期性能上限最高，但需要资产流水线和部署基础设施，不适合本轮本地项目优化。

## 实施设计

1. 首页先呈现可操作的检索与全国目录，地图模块在浏览器空闲阶段启动；加载状态降为地图区域内的非阻断提示。
2. Three.js 建立三档配置：地形细分、海面细分、DPR、云数量、目标帧率、后期特效和待机自转分别控制。
3. 首帧使用基础 renderer 尽快交付；仅高档后台动态载入 Bloom 与调色模块，完成后无缝增强。
4. 渲染循环按档位限帧；低档静止时停止海浪、云层和自动旋转，仅在交互、飞行、尺寸变化时唤醒。
5. 鼠标悬停检测按动画帧节流，触屏完全跳过悬停；手势追踪 pointerId，双指后禁止误触，触屏轻点容差扩大。
6. WebGL 不可用或上下文丢失时不刷新页面，展示全国目录入口作为可靠降级路径。

## 验收

- 高、标准、节能三档均能进入省份；移动端轻点、单指旋转和双指缩放互不误触。
- 加载期间可立即使用全国目录；WebGL 失败不会造成页面刷新循环。
- TypeScript、相关 ESLint、生产构建通过；桌面与 390px 手机视口控制台无错误。

## 实施结果

- 标准/节能设备的地图主包由约 `373.84 kB gzip` 降至 `268.03 kB gzip`，减少约 28%。
- `worldGeo`（`102.69 kB gzip`）与 Bloom/调色后期均改为仅高画质异步加载。
- 直达博物馆详情不会请求地图模块；目录在地图准备期间即可操作。
- 390px 视口验证拖动不误选、轻点省界可进入，运行控制台无错误。
