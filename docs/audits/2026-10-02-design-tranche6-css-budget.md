# 设计品质第六轮：删掉 43% 的样式包，把性能指标从"网络晴雨表"变成可比数字

日期：2026-10-02。上一轮结尾我列了三件事，这一轮做完两件半。

## 一、自检升级：限速档测量 + 样式包预算（v5）

### 1. 限速档 LCP（Slow 4G）

在自检里加了一次 **Slow 4G 限速导航**（`Network.emulateNetworkConditions`：1.6Mbps 下行 / 750kbps 上行 / 150ms RTT），用它的 LCP 作为评分依据，不限速的数字只作参考。

**为什么必须这样**：上一轮从本机测线上冷启动得到 5–14 秒，而本轮同环境实测**不限速 7560ms 竟然比限速档 3192ms 还差** —— 这恰好证明瓶颈是本机到 CDN 的链路，而不是页面。用限速档可以把"网络因素"标准化，得到可比数字。

**本地结果：Slow 4G 下 LCP = 1284ms**（阈值 2500ms，余量 1.2 秒）。

### 2. 渲染阻塞样式包预算

新增判据「主样式包 ≤80KB」，因为它是**首帧关键路径**上的阻塞资源。

## 二、顺手挖出的大鱼：53 个死代码组件撑大了样式包

查样式包为什么有 133KB 时发现：`src/components/ui/` 下有 **53 个 shadcn 组件（172KB 源码），在 ui 目录之外零引用** —— 纯死代码。而 Tailwind 会为**扫描到的每个类名**生成 CSS，所以这些从未使用的组件一直在往渲染阻塞的样式包里塞东西。

核实与删除都做了路径校验（确认绝对路径、确认文件数 = 53 才执行删除）：删除 53 个未引用组件。**顺带**前一轮发现的 `accordion-*` 关键帧也一并消失。

| 指标 | 删除前 | 删除后 |
| --- | --- | --- |
| 主样式包（渲染阻塞） | **133 KB** | **69 KB** |
| 全部 CSS | 151 KB | 87 KB |
| 首屏 JS | 320.7 KB | **313.4 KB** |

删除后 180 条单元测试与四套 E2E 全过，无样式回归。

### 退场速度：我自己引入又回退的第二处

上一轮为了让画作更早开始下载，我去掉了开场画作的 `rendererReady` 门控。结果本轮 `e2e-intro` **稳定失败**：`skip took 243.7ms`（阈值 200ms），两次测量 243.7 / 244.5ms —— 稳定复现，不是负载。原因是常驻的图层让开场卸载变慢。

**已完整还原门控**：首屏质量由「内联海报 + 无第三方字体 + 69KB 样式包」承担，不需要牺牲开场手感去换。还原后 `e2e-intro` 恢复 **5/5**，冷启动 LCP 仍为 692–1300ms。

### 一处测量耐心调整（判据本意不变）

`e2e-detail-prefetch` 的 "idle provenance warm" 等的是**浏览器空闲回调触发的 1 个请求**，在七套件连跑的负载下 20 秒默认等待会不够（单独跑稳定 7/7，探针实测也确认恰好 1 个请求）。已把该等待放宽到 45 秒，**判据仍然是"恰好 1 个 provenance 请求"**，没有放松检查。
