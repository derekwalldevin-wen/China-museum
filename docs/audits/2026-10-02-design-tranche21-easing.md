# 设计品质第二十一轮：缓动语义化（有效取值 6 种 → 3 种）

日期：2026-10-02。上一轮立住了动效的"时长尺度"，这一轮做另一半——**缓动（easing）**。过程中又抓到一个"意图与实效不一致"的隐蔽 Bug。

## 一、先修测量：我上一轮的解析是错的

上一轮的探针把 `cubic-bezier(.2,.7,.2,1)` 按**逗号**切开，得到 `1)×22`、`0.2×18` 这种垃圾输出，缓动种类数完全不可用。这一轮改成**按括号配平切分**：

| 口径 | 种类数 |
| --- | --- |
| 声明值 | **13 种** |
| **有效计算值** | **6 种** |

有效值明细：`ease`×115（通用对称曲线，占绝大多数）、`cubic-bezier(0.2,0.7,0.2,1)`×49，以及 **4 条近乎重复**的自定义曲线：

```
cubic-bezier(0.2, 0.78, 0.18, 1)   cubic-bezier(0.22, 0.72, 0.22, 1)
cubic-bezier(0.22, 0.75, 0.2, 1)   cubic-bezier(0.2, 0.8, 0.2, 1)
```

这四条表达的是**同一个意图**（起步快、收尾缓），差别没人能感知——和上一轮时长的情况一模一样。

## 二、建立缓动语义 token 并收敛

```css
:root {
  --ease-out: cubic-bezier(.2, .7, .2, 1);   /* 进场/落定：起步快、收尾缓 */
  --ease-in: cubic-bezier(.4, 0, 1, 1);      /* 退场/离开 */
  --ease-in-out: cubic-bezier(.4, 0, .2, 1); /* 状态切换 */
}
```

把 12 处近重复曲线收敛到 `var(--ease-out)`。**有效缓动 6 种 → 3 种**。

## 三、抓到一个"意图与实效不一致"的 Bug

收敛脚本里我写了这个守卫：

```js
if (!styles.includes('--ease-out')) { /* 写入 token 定义 */ }
```

问题是：**替换动作先生成了 `var(--ease-out)` 引用**，于是守卫误判"已存在"、**跳过了 token 定义**。结果那 12 处声明引用了未定义变量 → 浏览器回退成默认 `ease` ——**恰好是我最想避免的那个曲线**。

它没有报错、页面也正常，只有**重新测量有效值**才露馅：

| 时点 | `cubic-bezier(0.2, 0.7, 0.2, 1)` 有效条数 | 含义 |
| --- | --- | --- |
| 收敛后（缺定义） | 49 | 12 处没生效，仍是默认 ease |
| 补上定义后 | **52** | 12 处真的解析到目标曲线 ✓ |

**教训**：改完必须量"有效值"，不能靠"我写对了"来判断。这条已记入踩坑清单（第 27 条）。

## 四、如实说明：还没动 `ease`

有效缓动里 `ease`（对称曲线）仍占 115–205 处。把它整体换成 `--ease-out` 会让**所有进场更快落定**——这是**手感取向**，不是对错问题，而且会波及全站观感。所以这一轮**只收敛了近重复项**，把这条作为**带数据的建议**留给你定：

> 建议：把过渡里的裸 `ease` 换成 `--ease-out`（进场更利落）；退场类换成 `--ease-in`。需要我一并做的话说一声。
