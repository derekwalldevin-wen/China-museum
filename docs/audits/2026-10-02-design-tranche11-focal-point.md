# 设计品质第十一轮：补上"一屏一个焦点"，并把反复踩的坑从代码上根治

日期：2026-10-02。这一轮做量表里最后一条没有量化的设计项——"一屏一个焦点"。**结论是：当前设计本来就合格，这一轮是"验证"而不是"修改"。**

## 一、先量：首屏到底有几个"抢注意力"的元素

判据定义：首屏内（可见层）

- **抢眼文本**：字号 ≥ 1.6× 正文字号，且元素自身直接承载文字；
- **抢眼媒体**：面积 ≥ 20% 视口的图片/画布（按最外层去重）。

| 画面 | 抢眼文本 | 抢眼媒体 |
| --- | --- | --- |
| 故事页·桌面 | **1**（h1「一口钟，为什么可以发出不止一个音？」44px） | **0** |
| 故事页·手机 | **1**（同一 h1，28px） | **0** |
| 首页·桌面 | **1**（荐读标题「现场看过它」26px） | **1**（地图 69%，本就是画面主体） |

也就是说：**每个首屏只有一个同级别的注意力焦点**，符合"一屏一个焦点"的要求。于是把它固化成判据（4 分），用于**防未来回归**——以后谁往首屏塞第二个大标题或第二张大图，自检会立刻报出来。

## 二、同一个坑第三次出现，这次从代码上根治

量首屏时又出现了熟悉的一幕：**「山河入画」被算成故事页的抢眼文本**（39px）。它其实是**背后地图层的标题**——故事页打开时地图仍是 `aria-hidden`/`inert`，但元素依然参与布局。

这个坑已经出现三次了：

1. 字号下限：误报 76 处违规（其实全在隐藏的地图层）；
2. 动效统计：把隐藏层的动画算进来；
3. 视觉焦点：把地图标题算成故事页的焦点。

所以这次不再逐个打补丁，而是在探针里定义**统一的可见层获取方式**，所有统计循环都走它：

```js
const visiblePool = selector =>
  [...document.querySelectorAll(selector)].filter(element => !element.closest('[aria-hidden="true"], [inert]'));
```

媒体计数同时按"最外层"去重（`picture > img`、`picture > svg` 不再重复计三次）。
