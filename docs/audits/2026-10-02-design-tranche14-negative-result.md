# 设计品质第十四轮：一次被 E2E 拦下的"改进"（阴性结果报告）

日期：2026-10-02。这一轮的结论比较特殊：**产品代码最终零改动**，但我认为这个结论本身值得留下——因为它挡住了一个会伤害正确性的"优化"。

## 一、起点：手机上地图的点击目标确实偏小

实测（390×844）：

| 命中区 | 手机 | 桌面 |
| --- | --- | --- |
| 印章标签命中圈 | **17×17px** | 44×44px |
| 省界形状 ≥44×44 的比例 | 8/34 | 29/34 |
| 最小的省（上海）形状 | **7×7px** | — |

手机把地图缩到约 0.49 倍，东部小省的可点区域只有一二十像素。这看起来是个明确的可用性缺口。

## 二、尝试一：给省界加"透明加宽描边"

做法：给每个省界再画一条 `stroke: transparent; stroke-width: 22; pointer-events: stroke` 的路径，视觉不可见、只扩大命中区。

**验证方法**：在小省（北京/天津/上海/海南）形状外侧取点，看 `elementFromPoint` 返回什么；并做对照（临时把描边宽度设为 0）。

**结果**：有描边与无描边的返回值**完全一致**——采样点都被**标签命中圈**截获，说明这条描边在这个布局里没有起到作用。
→ 按"没被证实有效就不上线"的原则，**撤回**。

## 三、尝试二：把标签命中圈从 17px 放大到 44px

做法：手机端 `.scroll-label-hit { r: 52px }`，实测命中圈变成 **44×44（34/34 达标）**，看起来正是想要的效果。

**然后 `e2e-map` 把它拦下来了**：

```
[e2e-map] Error: Timed out: mobile opens 北京市
```

原因很清楚：**放大的圆形命中圈在京津冀这类密集区互相重叠**，点击"北京"落到了邻省的圈上。降到 r=32（约 29px）后依然复现，只是误触目标换成了河北。

**点北京却打开河北，比"目标偏小"严重得多**——前者是正确性错误，后者只是操作费力。所以再次**撤回**，`e2e-map` 立刻恢复 **7/7**。

## 四、结论与留档

1. **本轮产品代码零改动**，`src/` 已回到上一轮状态（构建产物一致，无需重新部署）。
2. 手机端地图的点击目标确实偏小，这是**已知取舍**：圆形命中圈在地理密集区无法安全放大。
3. 真要解决，需要**按省自适应**：命中半径随该省形状面积与其邻省间距变化，或在放大/选中后才放大命中圈。这属于信息设计改动，需要单独一轮（也应先与你确认方向）。
4. 自检里保留了这项测量（`mapHit`，记录在 `design-audit.json`），但不作为判据——**一个已被实验否定的目标不该写进尺子**。
