# 设计品质自检标准（design-audit · v4）

目标：把"获奖级品质"落成**可复跑、可比较**的量化检查。每次改版后跑一次，分数只允许上升。

```powershell
npm run build
# 起无头浏览器（任意调试端口），然后：
$env:HUAXIA_CDP_ENDPOINT='http://127.0.0.1:11520'
$env:HUAXIA_E2E_URL='https://huaxia-museum-atlas.pages.dev/'   # 或本地 preview 地址
node scripts/design-audit.mjs
```

输出：`docs/audits/design/design-audit.json`（全部原始测量）与 `design-audit.md`（分项清单）。

## 测量口径的坑（8 条，全部踩过并修正，留档以免重犯）

1. **隐藏层不计入**：故事页打开时地图层仍是 `aria-hidden`/`inert`，曾被算成 76 处字号违规。
2. **图片不是"全部 lazy"才好**：首图 eager 才是 LCP 正解。
3. **关键帧只统计页面上真正在用的动画名**（Tailwind/shadcn 带进来但未使用的不计）。
4. **被 `prefers-reduced-motion` 压到 0.01ms 的动画不算"在动"**，按可感知动效（>50ms）判定。
5. **性能观察器必须在导航前注入**（`Page.addScriptToEvaluateOnNewDocument`）。
6. **就绪条件必须按路由判定**：故事路由上地图的 34 个省份也在 DOM 里，用 `or` 连接会让条件被地图提前满足，导致在故事尚未挂载时就开始测量。
7. **LCP/CLS 必须冷启动测量**：禁用 HTTP 缓存。热缓存下首页 LCP 会得到 140ms 这种失真数字，冷启动才是 2.4s 量级。
8. **异步出现的交互入口要等**：作品图放大按钮随图片元数据异步出现（线上比本地慢），等待后再取数。
9. **第三方字体可能比页面本身还慢**：本环境实测 Google Fonts 样式表请求要 **16.7 秒**，把 `document load` 拖到 17 秒（首帧实测只要 134ms 就能挂载）。已彻底移除第三方字体，改用系统字体栈。
10. **线上 LCP 要按限速档解释**：从本机测线上冷启动得到 5–14 秒，但同环境第三方请求要 16.7 秒 → 那是本机到 CDN 的网络问题，不是页面问题。下一步用 `Network.emulateNetworkConditions` 做限速测量，才能得到网络无关的可比数字。
11. **SVG 里的 `font-size` ≠ 屏幕上的大小**：地图 SVG 随视口缩放。桌面上 11px 的省简称实际有 14.8px（达标），而手机缩放 0.49 倍后 9px 只有 **4.4px**（几乎读不了）。**必须按有效尺寸判定**：`有效 = fontSize × rect.height ÷ (fontSize × 1.15)`。改字号时**印章底板要同步缩放**，否则字溢出底板、密集处就会显得杂乱。
12. **分项之和必须等于维度上限**：出现过两次"102/100""101/100"，都是调上限时忘了同步分项；改完必须实跑一次确认总分是 100。
13. **端到端"事件时长"在无头环境里不可用**：`PerformanceObserver(type:'event')` 量出的 pointerenter/pointerdown/click 时长会高度一致（实测都是 152ms 或 400ms），说明该值被**输入派发开销**主导，不是我们的代码。改用 **`longtask` 观察器（>50ms 主线程阻塞）**，并在测量前清空采样（否则"跳过开场"这类一次性长任务会污染结果）。端到端数值保留为参考并在判据里注明。
14. **长任务必须归因到交互**：只"清空采样再点击"不够——页面自身的后台工作（延迟预取回调、GC）也会落进窗口。必须只统计**点击后 250ms 内启动**的长任务；曾因此误报"线上 2 个 170ms"，经四组对照实验（图片未就绪/已解码 × 本地/线上）证明**四种情形均为 0 长任务**，是测量方式的锅。
15. **隐藏层混入统计——这个坑出现过三次**（字号下限误报 76 处、动效统计、视觉焦点把地图标题算成故事页焦点）。现已统一为探针内的 `visiblePool(selector)`：过滤 `[aria-hidden="true"], [inert]`，所有统计循环都必须走它。媒体类元素还要按"最外层"去重（`picture > img/svg` 不能重复计数）。
16. **压在画作/渐变上的文字必须按真实像素测对比度**：DOM 方法只读 `background-color`，遇到 SVG `fill` 底板与 CSS 渐变会回退成深色默认值，把"深字＋浅底"误判成"深字＋深底"（实测把 7.51 算成 1.76）。正确做法：**等元素稳定**（不透明度 1、无进行中动画）→ 截取元素区域 → 前景取**声明色**（SVG 取 `fill`）→ 背景取切片中**最亮 20% 的中位数**。不要用 2%/98% 分位，小字的抗锯齿像素会让它剧烈抖动。

## 排版与字体的自包含决策

**不再引用任何第三方字体**（`fonts.googleapis.com` 已从两个入口 HTML 移除）。字体栈全部落到系统字体：

- 衬线（正文）：`'Songti SC', 'Noto Serif SC', 'Source Han Serif SC', 'Source Han Serif CN', 'SimSun', serif`
- 无衬线（界面）：`-apple-system, 'PingFang SC', 'HarmonyOS Sans SC', 'Microsoft YaHei', 'Noto Sans SC', system-ui, sans-serif`
- 题字：`'KaiTi', 'STKaiti', 'Kaiti SC', serif`

代价与收益：代价是各平台字形略有差异（Windows 宋体 / macOS 宋体-简 / Linux 思源宋体）；收益是**零第三方请求**、首帧从 1.8 秒降到百毫秒级、`document load` 从 17 秒降到 0.17 秒，且没有隐私与可用性风险。

## v4 仍覆盖不到的部分（诚实说明）

**100/100 依然 ≠ 获奖级。** 剩下这些是后续要补的：

1. **首屏 LCP 余量很小**：冷启动实测 **2388ms**（阈值 2500ms），线上有一次测到 3588ms；LCP 元素是我们自己开场的 SVG 文字「山河入画」。下一步要做的是把开场首帧从"等 JS 挂载"改成"HTML/CSS 即刻可见"，以及自托管/子集化中文字体，砍掉第三方字体往返。
2. **地图标注排版**：SVG 地图仍有 7–11px 的 `.scroll-*` 标注 10 处，牵动布局，需配视觉 QA 单独做。
3. **手势连续性**：移动端游线前后站的滑动切换（目前只有按钮）。
4. **INP**：需要真实交互序列才可测。
5. **"一屏一个焦点"的定量判据**（目前只有字号级差）。
6. **圆角/描边/阴影 token 化**（间距已达标）。
