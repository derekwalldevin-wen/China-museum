# 设计品质第十二轮：对比度要按**真实像素**测——我的 DOM 方法误报了三个"不达标"

日期：2026-10-02。这一轮查首屏对比度（地图红字＋宣纸底，评审最容易挑的地方），过程里又推翻了自己一次。

## 一、DOM 方法报出三个"不达标"，全是误报

先按常规做法（读 `color` + 向上找 `background-color`）测：

| 元素 | DOM 方法 | 判断 |
| --- | --- | --- |
| 地图省简称 | 1.76 | ✗ 不达标 |
| 地图件数 | 3.19 | ⚠ |
| 荐读标题 | 1.33 | ✗ 不达标 |
| 荐读说明 | 2.22 | ✗ 不达标 |

**但这四个数字全错**：省简称坐在 **SVG 印章底板**上（`fill` 画的，不是 `background-color`），荐读卡片坐在 **CSS 渐变**上（`background-color` 是透明的）。我的函数找不到背景，回退成了深色默认值，于是把"深字＋浅底"算成了"深字＋深底"。

## 二、改成按真实像素测

做法：截取元素区域 → 在页面里用 canvas 取像素 → 前景用**声明色**（SVG 取 `fill`），背景用**切片中最亮 20% 的中位数**。

中间还迭代了两次：

1. **第一版用 2%/98% 分位**：结果抖动很大（同一元素在 3.33 / 4.79 / 7.18 之间跳），因为小字的**抗锯齿像素**主导了暗端，而且有时会**截到淡入动画中途**的画面 → 加"等元素稳定（不透明度 1 且无进行中动画）"。
2. **第二版固定前景色**：前景取设计声明的颜色（不受抗锯齿影响），背景仍按像素采样 —— 数字才稳定下来。

修正后的真实值：

| 元素 | DOM 方法（错） | **像素级（准）** |
| --- | --- | --- |
| 地图省简称 | 1.76 | **7.51** ✓ |
| 地图件数 | 3.19 | **4.09** ✗ ← 真缺口 |
| 荐读标题 | 1.33 | **10.3** ✓ |
| 荐读说明 | 2.22 | **7.81** ✓ |

## 三、真实缺口只有一个：地图件数

12px 的省份件数（`#6a604a`）在宣纸底上只有 **4.09**，未达 AA 要求的 4.5。把它加深到 `#554e39`：

| 元素 | 改前 | 改后 |
| --- | --- | --- |
| 地图件数 | 4.09 | **5.46** ✓ |
| 荐读说明（顺手留余量） | 7.81 | 7.81（文字色另行加深过） |

线上复测：省简称 **7.31** · 件数 **5.46** · 荐读标题 **10.3** · 荐读说明 **7.81** —— 全部达标。

## 四、量表 v8：对比度维度补"像素级"

新增判据：**首页像素级对比度全部 ≥4.5**（地图省简称／件数／荐读标题／荐读说明），2 分；原两项各降 1 分以配平。这条判据专门覆盖"文字压在画作或渐变上"的场景——DOM 方法在那里完全失效。
