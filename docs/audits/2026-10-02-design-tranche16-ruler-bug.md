日期：2026-10-02。这一轮用像素级方法补量了两个从未量过的面；两个面都健康，但过程中**发现我的自检脚本里有一个取值 Bug**——值得单独记一笔。

## 二、抓出我自己尺子里的一个 Bug（值得记）

现象：判据显示

```
✗ 故事目录卡片像素对比度 ≥4.5（标题 n/a／问题 n/a／…）
```

但同一次运行的 JSON 里，五个值**明明都在**（11.18…8.99）。报告和 JSON 自相矛盾。

排查过程（三次假设、两次推翻）：

1. 以为"判据求值早于测量"→ 查行号：测量在 401 行、判据在 590 行，顺序没问题；
2. 以为"包装脚本跑了两次"→ 读包装脚本：只跑一次；
3. 直接打印调试值，**真相出来了**：

```
DEBUG 目录对比度最小值 = 0 | 明细 = {"title":11.18,"question":12.19,...}
```

**根因**：自检里的 `pixelContrast()` 返回的是一个**数字**，而我在独立探针里写的同名函数返回的是 `{ ratio, size }` **对象**。判据按对象取值 `?.ratio`，从数字上取 `.ratio` 得到 `undefined`，`?? 0` 又把它变成 0，于是最小值恒为 0、标签恒显 `n/a`。

**教训**：同一个概念的辅助函数在两个文件里**契约不同**，是最容易骗过自己的 Bug——因为两边"看起来"都在正常工作。修法：判据直接读数字，并加一行注释写明该函数返回数字。
