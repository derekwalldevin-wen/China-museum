# 设计品质第二十七轮：面板滚动行为、返回控件 44px，以及一条"会抖"的对比度

日期：2026-10-03。这一轮体检 390 下的**馆藏面板滚动行为**，顺带抓到一条**余量不足的对比度判据**——它的波动区间有一半会掉到 AA 之下。

## 一、面板滚动行为：健康

| 检查 | 结果 |
| --- | --- |
| 滚动容器数量 | **1 个**（`flex-1 overflow-y-auto overscroll-contain`）✓ |
| `overscroll-behavior-y` | **`contain`** ✓（面板滚到底不会把背后页面带走） |
| 背后（document）是否可滚 | 不可滚（`scrollHeight === clientHeight`）✓ |
| 关闭/返回控件是否始终可达 | 是，固定在面板顶部 ✓ |
| 面板内 <24px 的点击目标 | **0 个** ✓ |

滚动链这类移动端常见缺陷在这里**本来就被处理过**（`overscroll-behavior: contain`），属于验证而非修补。

## 二、一处真实改进：返回控件在移动端只有 32px

面板顶栏「← 返回北京市」实测 **97×32px**。

- WCAG 2.5.8 的下限（24px）**达标**；
- 但项目自己给关键控件（跳过链接、章节索引行）定的是 **44px** 标准 → 这里不一致。

改法：移动端 `min-h-[44px]`、桌面 `md:min-h-0`（保持紧凑），并加 `inline-flex items-center` 居中。

| 视口 | 改前 | 改后 |
| --- | --- | --- |
| 390 | 97×**32**px | 97×**44**px ✓ |
| 1440 | 101×32px | 101×**32**px（不变）✓ |

量表补上这条：**馆藏面板返回控件在 390 ≥44px**（移动端维度内部腾挪：无溢出 3→2 分，上限与总分不变）。

## 三、抓到一条"会抖"的对比度判据

自检忽然报 98/100：

```
✗ 首页像素级对比度全部 ≥4.5（地图省简称 7.51／件数 3.94／荐读标题 10.3／荐读说明 7.81）
```

而此前多轮都是 **4.92**。复跑两次又都是 4.92 —— 说明这条判据**在 3.9–4.9 之间波动**。

原因不是"测量错了"，而是**被测对象本身余量不足**：地图上的省份件数**直接压在手绘长卷上**，底色随画面区域变化；采到较亮的画面区时对比度就掉下来。

处理：把件数字色再加深一档（`#554e39` → `#3f3a29`），然后**连测三次**：

| 次数 | 件数对比度 |
| --- | --- |
| 1 | 6.75 |
| 2 | 6.75 |
| 3 | **5.22** |

最差情形从 **3.94（不达标）** 提升到 **5.22（舒适达标）** ✓。这不是"重跑一次让它过"，而是**把最坏情况也做进安全区**。
