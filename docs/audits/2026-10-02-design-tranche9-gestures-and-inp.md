# 设计品质第九轮：移动端手势连续性 + 交互响应度量（两次换尺子）

日期：2026-10-02。这一轮做了两件事：给故事页加左右滑动切换前后站；以及给量表补"交互响应"。后者的过程比结果更有价值——**我换了两次尺子**。

## 一、左右滑动切换游线前后站

故事页支持在移动端左右滑动切换游线的前一站/下一站，与底部按钮等价：

- **只认明显的水平滑动**（位移 ≥64px 且 ≥纵向位移的 2 倍），纵向阅读不受影响；
- **避开可横向滚动区域**（文物长卷阅读器、放大视图），不抢走它们的手势；
- **按钮路径保留**——键盘与读屏用户走按钮，符合"手势必须有单指替代方案"的要求；
- 滑动结束后按现有逻辑保存阅读位置。

**先手工验证再固化为测试**（真实触摸事件：touchStart → 3 段 touchMove → touchEnd）：

| 动作 | 结果 |
| --- | --- |
| 左滑 | `hub-zhy → gb-jgs` ✓ 切到下一站 |
| 右滑 | 回到 `hub-zhy` ✓ |
| 纵向滑动 | 不切换 ✓ 未误触发 |

随后把这段固化进 `e2e-stories`，该套件通过数从 **460 → 461**。

> 顺带修了一个测试结构问题：我一开始把新检查追加在**汇总输出之后**，它跑了却不计入 `passed`（仍是 460）。把它移到汇总前才是真的被覆盖。

## 二、交互响应：我换了两次尺子

### 第一次：端到端事件时长（错的）

先用 `PerformanceObserver`（`type: 'event'`）量"点击到下一次绘制"，线上得到 **800ms**。但打印每次交互的明细后发现——**所有事件类型的时长高度一致**：

```
pointerover 152ms · pointerenter 152ms · mouseover 152ms · pointerdown 152ms · click 152ms
pointerleave 400ms · pointerdown 400ms · click 392ms
```

真正的 JS 处理不可能让 `pointerenter` 和 `click` 一样慢。这说明该值被**无头浏览器的输入派发开销**主导，不是我们的代码。**这个数字不能用来评价网站。**

### 第二次：交互期间的长任务（对的）

改用 `longtask` 观察器（>50ms 的主线程阻塞），在测量前清空采样（否则会把"跳过开场"这种一次性长任务算进来），只统计真实交互：

| 环境 | 交互期间长任务 |
| --- | --- |
| 本地 | **0 个（最长 0ms）** ✓ |
| 线上 | **2 个（最长 170ms）** ⚠️ |

端到端事件最大值（本地 576ms／线上 888ms）保留为**参考值**，并在判据文案里注明"无头环境派发开销会主导该值"。

### 线上那 2 个长任务：我尚未查清，不编结论

已排查：地图层**没有常驻渲染循环**（只有一次性 rAF），开场动画在跳过即卸载。所以更可能来自**图片解码或网络到达时机**（故事页首图 detail 图 543KB）——但这需要下一轮专门测，我没有证据不会写成结论。
