# 文物详情图与长卷打开速度优化报告

日期：2026-09-16  
生产站：https://huaxia-museum-atlas.pages.dev/  
不可变部署：https://437b725b.huaxia-museum-atlas.pages.dev/

## 结论

详情图现在在明确的鼠标、键盘或触控意图出现后，先复用按馆溯源缓存，再预载该文物已经审计的detail响应式候选。详情框架仍立即打开，完整图在decode完成后显影，长卷完成尺寸判定后才标记为可交互。没有操作时不预取详情：390×844首屏继续严格为2张card图片、37,140 B。

正常网络下，手机普通详情从1,350.7ms降至516.8ms，手机长卷从1,337ms降至432.7ms；分别缩短61.7%和67.6%。桌面普通详情缩短27.9%，桌面长卷缩短52.7%。

## 实现

- 桌面pointer enter需停留120ms，避免鼠标扫过整排卡片造成浪费；键盘focus、pointer down和touch start立即预取。
- 预取只调用`loadArtifactImageInfo`并读取按馆payload中的detail delivery，不推断文件名、不改变图片选择。
- 动态image preload携带正式图片相同的`srcset`与`sizes`，由浏览器选择原有尺寸档位；正式详情继续使用相同WebP/JPEG/PNG回退链。
- 元数据Promise与图片key均去重；快速连续切换时最后一个URL和图片状态优先，不会被先前请求覆盖。
- 普通器物保持4:5框架；长卷保持原clamp高度。decode前显示“正在显影/正在展卷”及安全卡片预览，避免空白和布局跳动。
- 长卷在decode、自然尺寸判定、横向布局和进度初始化完成后才设置ready。

## 剩余风险

- 真实iPhone Safari和低端Android尚未真机验收；当前触控证据来自无头Edge原生触摸事件。
- 极弱网下大图传输时间仍由文件字节和带宽决定；本轮没有以降低清晰度换取数字改善。
- touch/pointer意图发起后即使用户取消打开，已开始的单件预取会保留在浏览器缓存；它不改变URL或界面状态，但可能消耗该单件详情流量。
- 桌面120ms悬停门槛是防误触与加速之间的折中；极快点击没有足够预取窗口，仍会依赖稳定占位。
