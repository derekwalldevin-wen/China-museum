# 设计品质第十九轮：验证两条我一直"宣称"的中文字排细节

日期：2026-10-02。这一轮做的是**证伪自己的宣称**：中西文自动间距、数字等宽——这两条从项目早期就写在目标里，但从未实测过。结果一真一假。

## 一、中西文自动间距：**确实生效** ✓

对照实验（同一样本「汉字ABC汉字」，同一字体栈与字号，只改一个属性）：

| 属性 | 样本宽度 |
| --- | --- |
| `text-autospace: normal` | **107.42px** |
| `text-autospace: no-autospace` | 103.17px |
| **差值** | **+4.25px** ✓ |

逐字数据同样支持：拉丁字母前后的汉字从 17px 变成 **19.13px**，多出来的正是自动间距。引擎侧 `CSS.supports('text-autospace','normal')` 为真。

> 注意：本引擎里插入间距的关键字是 `normal`（`auto` 不被支持）。我早期写的就是 `normal`，这次终于有了数字依据。

## 二、数字等宽：**正文里是空转的** ✗（但结论是好的）

`font-variant-numeric: tabular-nums` 确实应用到了正文，但实测：

| 字体栈 | 数字逐字宽 | 不同值 |
| --- | --- | --- |
| 正文衬线（Songti SC 等）tabular-nums | 9.48, **8.02**, 9.5, 9.48, … | 7 个 |
| 同一字体 proportional-nums | 9.48, **8.02**, 9.5, 9.48, … | 7 个 |

两者**完全一致**——说明**衬线字体栈里没有等宽数字**，这条声明在正文里不起任何作用。

而界面字体（无衬线栈）**天生等宽**：数字逐字宽 6.67–6.69，极差仅 **0.02px**（亚像素舍入），坐标与统计数字本来就对齐。

**结论是好的**：纸质书的通行做法正是"**正文用比例数字、数据列用等宽数字**"。所以正文的比例数字不是缺陷，是正解。

### 按事实整改

1. **正文**：删掉空转的 `font-variant-numeric: tabular-nums`，改为如实注释（说明衬线栈无等宽数字、正文按书面惯例用比例数字）。
2. **数据读处**（页脚经纬、统计）：显式声明 `font-variant-numeric: tabular-nums`，保证将来回退到无等宽数字的字体时仍然对齐。

## 三、我自己的测量方法又错了两次（已记）

1. 第一次探针跑在**首页**上，于是读到的"正文字体设置"其实是 `body` 的默认值（`font-variant-numeric: normal`），差点得出错误结论；
2. 第一次的对照容器放在 `left:-9999px`，量出来宽度是 **0**。改成"视口内 + `visibility:hidden`"（仍参与布局）后才有可信数字。
