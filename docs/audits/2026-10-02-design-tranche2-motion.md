# 设计品质第二轮：给正文装节奏（滚动驱动 + 章节目录），量表升到 v2

日期：2026-10-02。上一轮把"尺子"做出来（v1 只量硬指标）；这一轮**先把尺子补准**（v2 加入动效/状态/结构/键盘），再落地动效，两个动作互相校验。

## 一、动效：零 JS，全部可降级

| 做了什么 | 实现 |
| --- | --- |
| **阅读进度条** | `animation-timeline: scroll(nearest)` 驱动 `scaleX`，元素 `position: sticky` 贴在滚动容器顶部。**没有加一行 JS，首屏包体不变（320,701 B）** |
| **章节浮现** | `animation-timeline: view()` + `animation-range: entry 6% cover 24%`，只动 `opacity` 与 `translateY` |
| **本文结构目录** | 四个章节的锚点，每行 44px（符合本项目既定的触控标准），键盘可直达；章节加 `id` 与 `scroll-margin-top` |
| **降级** | `@supports` 包住滚动时间线；`prefers-reduced-motion: reduce` 时 `animation:none` + 已有全站 0.01ms 规则；不支持的浏览器（Firefox 160 之前）拿到完全静态、可读的版式 |

顺手修掉一处**一直没生效的动画**：`@keyframes loadSweep` 动的是 `left`，而其中一处宿主元素是 `static`（`left` 对静态元素无效），所以那条加载扫光其实没动；改成 `transform: translateX()` 后既真的动起来，也不再逐帧触发布局。

## 二、量表 v2（10 个维度）

新增四个维度：**动效与手感 16**、**交互状态 6**、**结构层级 6**、**键盘可达 4**，并重新配平总分到 100（排版 22 / 字号 6 / 对比 12 / 无障碍 12 / 移动 8 / 性能 8）。完整判据见 [`docs/audits/design/README.md`](design/README.md)。

**量表升级后分数先掉到 90**，因为动效两项当时确实是空的——这正是"先把尺子做准"的意义。修完动效后回到 **100/100**。

期间又修正了**我自己写错的三条判据**（都记录在 README 里）：
1. 动效统计把**隐藏层**算进去（故事页打开时地图层 `aria-hidden`/`inert` 仍在 DOM）；
2. 把被 `prefers-reduced-motion` 压到 0.01ms 的动画算成"在动" —— 改为按**可感知动效（时长 >50ms）**判定；
3. 关键帧检查统计了 Tailwind/shadcn 带进来但**页面没在用**的关键帧 —— 改为只统计运行时实际使用的动画名。

## 四、下一轮（v3 要量化的东西）

`README.md` 列出 v2 仍覆盖不到的七项。按"先量后改"的原则，下一轮先把量表和测量补上，再做：

1. **真实性能数字**：LCP / CLS / INP 实测（PerformanceObserver），这是评委和搜索引擎都看的硬指标；
2. **视觉焦点与层级**：一屏一个焦点、三级层次；
3. **图像工艺**：放大细节浏览、状态标记（原件／复制件／AI 示意）统一版式；
4. **一致性 token**：间距 4px 基准、圆角/描边/阴影 token 化；
5. **键盘全流程**：skip link、Tab 顺序、`aria-live`；
6. **地图标注排版**（7–11px 的 `.scroll-*`）：需要单独视觉 QA，不能盲改。
