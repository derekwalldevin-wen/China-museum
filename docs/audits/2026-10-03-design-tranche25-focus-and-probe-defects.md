## 二、真实缺陷：切换故事后焦点跑到"退出"按钮

现象（键盘路径）：在「本卷下一站」上按回车进入下一篇后，`document.activeElement` 是顶栏的 **「回到原处 ✕」（退出故事导览）**。

对键盘/读屏用户来说这很糟：**按下回车想看下一篇，焦点却"跳出了阅读流"**，而且新故事标题不会被播报。

根因：`StoryExperience` 有一个**挂载时把焦点放到退出按钮**的 `useLayoutEffect`（这是"打开导览"的正确行为）；但 App **按故事把该组件 key 掉**，所以每次切故事都重新挂载 → 该行为再次执行。我第一次用组件内 `ref` 判断"是否首次进入"，**被重挂载重置**，整段没生效。

修法：把"是否已打开过导览"放在**模块级**，并区分两种情形：

- 首次打开导览 → 焦点落在退出按钮（**保持原行为不变**）；
- 导览内切换故事 → 标记 `titleFocusPending`，等新故事标题渲染出来后聚焦它（`preventScroll`）。

## 三、我自己造的第一个问题：CDP 序列化报错

新检查加进去后套件红：

```
{"code":-32000,"message":"Object reference chain is too long"}
```

为了定位，我**临时**在 CDP 封装里加了一行错误日志，抓到出错调用：

```
Runtime.evaluate {"expression":"document.querySelector('.story-chapters p')","returnByValue":true, ...}
```

**是我写的**：`page.wait(...)` 传的是**裸表达式**，它返回 **DOM 节点**，而 `returnByValue` 无法序列化深层节点。套件约定必须写成布尔（`!!document.querySelector(...)`）。

处理：修成 `!!`，并**把临时诊断彻底还原**。还原后我检查了 `git diff`——发现自动还原**调换了两行顺序**，导致 `timer` 在初始化前被引用（TDZ 报错）。按原实现修回，最终 `headless-cdp.mjs` **diff 为空** ✓。

> 结论：**临时诊断用完必须核对 diff**，不能只看"日志里没有诊断字样了"。

## 四、我自己造的第二个问题：一条只在线下通过的判据

线上自检报 99/100：

```
✗ 图片渐显（首图过渡 property=all duration=0s）
```

但本地同样代码是 `property=opacity duration=0.52s`。原因：判据在**故事外壳就绪时**就测量，而生产（较慢）此时首图还没打上解码完成标记，探针回退抓到**另一个 `<img>`**（`transition-property: all` / `0s`）→ **假失败**。

修法：测量**先等 `img[data-artifact-image-ready]` 就绪**（最多 20 秒）再读计算样式。本地与线上复测均为 **100/100** ✓。
