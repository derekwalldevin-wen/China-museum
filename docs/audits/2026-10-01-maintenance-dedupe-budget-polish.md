## 二、首屏预算：把 59 条博物馆简介移出首屏包

先量化：首屏 JS = 共享 `client`(193,083 B) + `index`(134,741 B) = **327,824 / 328,000**，只剩 **176 B**。
- `client` 里**没有一个汉字**（纯框架/UI 代码，动它代价高、收益低）；文案全在 `index`，其中 **59 条博物馆简介 = 6,747 B**。
- 弹层（`ProvincePanel`／`MuseumDetail`）本来就是懒加载，检索也早就懒加载文物语料——只有简介字符串因为长在 `museums.ts`（地图首屏必需）里而被迫进首屏。

改法：
1. 新建 `src/data/museum-intros.ts`（简介的唯一出处，按 id 存放），从 `museums.ts` 剥离 `intro` 字段并从类型里移除；
2. 两个弹层从该模块取简介（它们本身是懒加载，简介随弹层分片到达，**面板交互没有多一次异步**）；
3. 检索改成**第一次输入时**动态 `import()` 简介模块，再用于简介字段加权（与既有的语料懒加载同一套路）；
4. `scripts/audit-artifacts.mjs` 的字段核查改为按 id 校验简介模块；
5. 新增 `scripts/museum-intros.test.mjs`（3 条）：简介与博物馆一一对应、无孤儿；简介不再出现在急加载模块里；弹层与检索都从懒加载模块取。

**结果：首屏 JS 327,824 → 320,694 B（省 7,130 B），余量 176 B → 7,306 B。** 因为弹层与检索都是既有懒加载路径，交互体验不变。
